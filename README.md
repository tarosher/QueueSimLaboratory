# QueueSimLab

[![MATLAB R2022b tests](https://github.com/tarosher/QueueSimLaboratory/actions/workflows/matlab-tests.yml/badge.svg)](https://github.com/tarosher/QueueSimLaboratory/actions/workflows/matlab-tests.yml)

QueueSimLab is a discrete-event simulation framework for queues and open, directed acyclic queueing networks, written in MATLAB. It grew out of a supermarket-queue course project. The simulator now keeps scenario configuration separate from event-handling logic, making it possible to compare queue policies, staffing choices, and network layouts without rewriting the engine.

It runs on **base MATLAB R2022b**; SimEvents and the Statistics and Machine Learning Toolbox are not required. Simulation time is measured in **minutes**.

**Versions:** [v0.2.0](https://github.com/tarosher/QueueSimLaboratory/releases/tag/v0.2.0) is the tagged release of the simulation engine and benchmark suite. The `main` branch also includes an optional graphical interface, Simulation Studio.

## Quick start

Clone the repository and set the MATLAB Current Folder to its root:

```bash
git clone https://github.com/tarosher/QueueSimLaboratory.git
cd QueueSimLaboratory
```

Run a two-server queue:

```matlab
cfg = qsim.defaultConfig();
cfg.simulation.arrivalHorizon = 120;
cfg.simulation.observationHorizon = 120;
cfg.source.type = 'poisson';
cfg.source.rate = 0.8;               % arrivals per minute
cfg.network.nodes.nServers = 2;

result = qsim.run(cfg);
fprintf('Mean wait: %.3f min\n', result.system.meanWaitStartedCohort);
```

To run the four-node branching network used in Benchmark B:

```matlab
cfg = qsim.network.benchmarkBConfig();
result = qsim.run(cfg);
disp([result.nodes.meanQueueLength]);
```

See the [quickstart guide](docs/QUICKSTART.md) for additional configurations and the [API reference](docs/API_REFERENCE.md) for input and output conventions.

## Supported models

- **Arrivals and service:** Poisson, scheduled, and supported renewal arrivals; exponential, deterministic, uniform, and lognormal service times, with explicit sequences where supported.
- **Service stations:** Single or multiple servers, pooled or dedicated FIFO queues, heterogeneous service speeds, finite capacities, and rejected arrivals.
- **Queue assignment:** Random, shortest-queue, or shortest-expected-wait selection for dedicated queues. The last policy uses estimated workload, not knowledge of future service times.
- **Networks:** Open directed acyclic graphs with branching and merging, probabilistic routing, fixed transfer delays, and per-node and end-to-end measurements.
- **Analysis:** Independent replications, Student-t confidence intervals, matched random inputs for controlled comparisons, flow checks, and staffing diagnostics.

## Reproducible experiments

The included scripts cover three questions:

| Benchmark | Question | Run |
| --- | --- | --- |
| A — Queue policies | How do pooled and dedicated lines affect waiting times under matched arrivals and service requirements? | `examples/run_m31_deepdive.m` |
| B — Staffing | Where should one additional server be placed in a multi-stage network? | `examples/run_m4_benchmarkB.m` |
| C — Topology and demand | How do serial and parallel network scenarios respond to different arrival loads? | `examples/run_m4_benchmarkC.m` |

Run the integrated analysis from the repository root:

```matlab
run('examples/run_m41_integrated.m');
```

It writes `outputs/m41_integrated/INTEGRATED_REPORT.md`, tables, MATLAB results, and figures. The `outputs/` directory is excluded from version control; results are generated by running the scripts. The [benchmark notes](docs/BENCHMARKS.md) explain the comparison controls and interpretation limits. For runtime measurements, see [performance benchmarks](benchmarks/README.md).

## Simulation Studio (main branch)

To work with single-node models without editing configuration scripts, open the MATLAB interface:

```matlab
qsim.launch
```

The interface supports a single scenario or a sweep over server counts. You can change arrival and service rates, queue policy, simulation horizons, seeds, and replication counts; save or load presets; and export CSV, MAT, and PNG results.

The current interface supports **Poisson arrivals** and **exponential or deterministic service** for single-node models. More general arrival processes and multi-node networks remain available through `qsim.run`. Automated checks cover the GUI's metric and range-parsing helpers, but do not replace manual testing of the desktop controls. See the [Simulation Studio guide](docs/GUI_QUICKSTART_ZH.md).

## Tests and reproducibility

Run the MATLAB regression suite from the project root:

```matlab
run('tests/run_all_tests.m');
```

For the full acceptance run, including Benchmarks A–C, generated files, and runtime measurements:

```matlab
run('tests/run_rc_acceptance.m');
```

The public [MATLAB R2022b CI run on commit `de92ff5`](https://github.com/tarosher/QueueSimLaboratory/actions/runs/42776601793) passed the 89-test regression suite, integrated acceptance checks, and GUI helper smoke tests on November 10, 2026. Tests include deterministic event traces, analytical M/M/1 and M/M/2 checks, capacity and flow conservation, seeded reproducibility, and network routing cases.

A separate [static preflight workflow](https://github.com/tarosher/QueueSimLaboratory/actions/workflows/static-checks.yml) checks repository packaging and documentation. It can also be run locally:

```bash
python tools/check_release.py
```

The static check does not execute MATLAB. Further details are in [validation notes](docs/VALIDATION.md).

## Modeling scope

- Simulations begin with empty systems and use a finite arrival horizon. `drain` finishes admitted work after arrivals stop; `truncate` retains unfinished work at the observation cutoff. These are not automatically steady-state estimates.
- Benchmark A matches exogenous arrivals and service requirements across policies. Benchmark B compares staffing changes with other network attributes held fixed. Common seeds do not imply identical event histories.
- Benchmark C compares complete network scenarios; it does not isolate a causal effect of topology, since service-time laws also differ across its configurations.
- Network routing is restricted to directed acyclic graphs. Cycles, fork/join synchronization, upstream spillback, shared inter-node resource constraints, and EV/energy coupling are not implemented. The framework does not include an automatic optimization solver.
